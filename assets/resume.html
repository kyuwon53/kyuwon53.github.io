결제완료 API가 정상 처리에도 401을 반환하던 문제 근본 원인 규명

  • 결제 완료 처리 요청에서 결제 동기화·주문 완료·트랜잭션 커밋·응답 생성까지 내부 로직은 모두 정상인데도 클라이언트에는 401이 반환되고, 인증이 필요 없는 엔드포인트로 바꾸면 재현되지 않는 크리티컬한 문제를 담당.
  • 로그를 심어 최종 응답 직전 dispatcherType=ASYNC, auth=false를 포착하고, Kotlin 코루틴 suspend 컨트롤러가 서블릿 ASYNC 디스패치로 재진입하면서 OncePerRequestFilter 기본 정책상 JWT 필터가 건너뛰어져 SecurityContext가 비워지는 것이 원인임을 규명.
  • 인증 필터가 재디스패치에서도 실행되도록 shouldNotFilterAsyncDispatch()·shouldNotFilterErrorDispatch()를 재정의해 결제 완료 응답을 안정화하고, 원인과 재발 방지 포인트를 팀에 공유.

주문/결제 신규 시스템 전환 — 패키지 상품·PG 전환·정산 리스크 해결 (PO 역할 병행)

  • 주문·장바구니·결제·상품·공제 정책이 강하게 결합되고 결제 중복·운영 지표 부재로 리스크가 누적된 레거시를, 패키지 상품 출시와 결제사(PG) 계약 변경이 겹친 상황에서 신규 시스템으로 전환.
  • 문화비소득공제 대상/비대상이 섞인 패키지 상품의 금액 분리와 결제·정산 기준을 정의하고, 고객이 주문을 나눠 결제하지 않도록 장바구니→주문→결제 한 흐름 안에서 해결.
  • 도메인 결합을 해소하도록 재설계하고 유니크 제약·행 잠금 기반 멱등성·중복 구매 방지, 결제·웹훅 처리 분리, 실패 주문 보정 스케줄러, 쿠폰·적립금 전환을 함께 진행.
  • 정산 오류 리스크를 줄이고 데이터 기반 운영 가시성을 확보했으며, 범위 정의·우선순위·커뮤니케이션까지 PO 역할을 병행한 성과로 전사 우수사원 포상·팀장 승진으로 이어짐.

30년 레거시 회원 시스템 무중단 전환 (30만+ 레코드)

  • 30년 레거시 플랫폼의 회원(30만+ 레코드)을, 신규 가입/로그인 시에도 레거시 서비스 이용에 차질이 없도록 무중단으로 이관.
  • userId→memberId 전환을 컬럼 추가 → 데이터 싱크 → 이중 기록 → 인증 정리 후 제거의 단계로 호환성을 유지하며 진행하고, 공용 회원 인증 API로 레거시와 신규 시스템이 공존하도록 설계.
  • 서비스 중단 없이 신규 스택으로 전환하고, 이후 다른 서비스도 점진적으로 이관할 수 있는 기반을 마련.

이벤트 기반 보상 시스템 구축

  • 개별 삽입·중간 레이어·큐 기반 비동기 3안을 비교해 현 인프라·일정에 맞는 @EventListener 기반 중간 레이어(수신·분기 → 라우팅 파사드 → 전략 핸들러)를 도입하고 미지원 트리거 방어용 기본 핸들러를 둠, 이후 큐 기반으로 확장 가능하게 설계.
  • 중복 참여 검증과 신·구 DB 동시 지급 정합으로 지급 신뢰성을 확보하고, 이벤트가 추가돼도 핸들러만 확장하면 되도록 개발 비용을 절감.
